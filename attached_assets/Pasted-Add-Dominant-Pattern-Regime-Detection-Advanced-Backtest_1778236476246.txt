Add Dominant Pattern Regime Detection + Advanced Backtesting Logic.

GOAL:
AI must identify the first/main shoe pattern early, lock it as the Dominant Pattern, detect only confirmed regime transitions, and sync all betting/backtesting logic with actual AI decisions.

--------------------------------------------------
1. Pattern Regime Definitions
--------------------------------------------------

Use Core History only:
- Banker/Player only
- Ignore Tie completely

Detect active regimes:
- N1 Pattern = immediate repeat/switch momentum
- N2 Pattern = two-hand structure
- N3 Pattern = three-hand structure
- N4+ Pattern = four-hand or deeper structure

--------------------------------------------------
2. Initial Dominant Pattern Detection
--------------------------------------------------

- Do NOT automatically use first 10 hands.
- Detect the first clear repeating structure from the beginning of Core History.
- Continue extending the structure until the first valid break appears.
- The structure before the break becomes the Initial Dominant Pattern.

Rules:
- Tie is ignored completely
- One break alone is NOT enough to change regime
- Initial Pattern locks only if:
  - at least 4 valid Banker/Player hands exist
  - stable structure existed before breaking

Track:
- Initial Pattern Range
- Break Hand #
- Break Type
- Candidate Pattern After Break

--------------------------------------------------
3. Dominant Pattern Lock
--------------------------------------------------

Once locked:
- ignore 1–2 anomalies
- treat small deviations as noise/error
- maintain current regime until valid transition confirmation exists

--------------------------------------------------
4. Valid Transition Rules
--------------------------------------------------

Allowed transitions only:

- N1 → N2
- N2 → N1
- N3 → N2
- N4+ → N3

Invalid transitions:
- N1 → N3
- N1 → N4+
- N4+ → N1
- N3 → N1

Ignore invalid jumps unless extremely confirmed.

--------------------------------------------------
5. Transition Probability Bias
--------------------------------------------------

Use default transition bias:

- N1 → N2 = 40%
- N2 → N1 = high probability
- N3 → N2 = high probability
- N4+ → N3 = high probability

AI should prefer these paths when evaluating regime changes.

--------------------------------------------------
6. Transition Confirmation Rules
--------------------------------------------------

AI must NOT bet during unconfirmed transitions.

Transition confirmation requires:
- candidate pattern appears 2 consecutive times
OR
- candidate pattern appears 3 times within last 5 valid Banker/Player hands
AND
- transition follows valid transition rules

Before confirmation:
- show:
  - TRANSITION WATCH
  - NO BET

After confirmation:
- update Dominant Pattern
- show:
  - PATTERN CONFIRMED

Betting resumes ONLY if:
- Markov agrees
- N-Strategy Core agrees
- Backtesting agrees

--------------------------------------------------
7. Anomaly Handling
--------------------------------------------------

- One break = anomaly only
- Two breaks without confirmation = maintain current regime
- Three breaks within five valid hands:
  - if matching valid transition path
  - begin transition confirmation process

Tie does NOT count as:
- anomaly
- confirmation
- regime reset

--------------------------------------------------
11. NO BET Handling
--------------------------------------------------

If AI Analysis outputs:
- NO BET

Then:
- any manual input (Banker / Player / Tie)
must NOT count as:
- win
- loss
- negative bet
- positive bet

Instead:
- record as:
  - SKIPPED

Effects:
- bankroll unchanged
- ROI unchanged
- confidence unchanged
- drawdown unchanged
- streaks unchanged

--------------------------------------------------
12. Tie Push Handling
--------------------------------------------------

If AI outputs:
- BET Banker
OR
- BET Player

And actual entered result is:
- Tie

Then:
- treat as PUSH

Do NOT count as:
- loss
- wrong prediction
- negative result

Effects:
- bankroll unchanged
- ROI unchanged
- confidence unchanged
- drawdown unchanged

Track separately:
- PUSH count
- PUSH rate %
